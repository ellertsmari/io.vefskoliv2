Portfolio schema review

A proposal for student portfolios: a PortfolioDraft type, a useDraft() hook and PortfolioView props. It is a well thought-out design and most of it stays exactly as written. What the proposal gets right

Eleven suggestions on top

Each is a small edit to the contract. None of them changes the overall design.

Decisions

Questions the suggestions raised, and where each one stands.

Decided

  • Portfolios are indexed.Students want to be found by name, so the pages are open to search engines and listed in the sitemap.
  • A hidden portfolio is visible only to its owner.A teacher who needs to help views the app as that student.
  • A draft in the browser is enough.Everyone works on their own laptop, so the draft is always where its owner is. Nothing unfinished is stored in the database.
  • Portfolios outlive the course, but the address changes.When a cohort finishes, its site moves to a Vercel domain. The portfolio is still there, under the new address.
  • Changing a slug breaks the old link.No redirects. That is how the web works, and this is a good place to learn it. The editor should say so before a new slug is saved.
  • Links are validated like the calendar's link field,with an https: check added (suggestion 6).

Yours to decide

  • Who can have a portfolio.Students only, or teachers too?
  • The route name.For example /portfolio/<slug>. Whatever you pick has to be added to PUBLIC_ROUTES (suggestion 3).
  • The name of profile.role.Keep it, or pick title or headline (suggestion 11).

Still being discussed

  • A local draft that is older than the stored version.With one laptop per student this can hardly happen, so the simplest rule may be enough: the local draft wins. Until that is settled, treat basedOn in the diagram as optional.
An idea, not a change: projects could point at the showcase

Group projects already have public pages under app/showcase, and the code there says students link them from portfolios and CVs. A portfolio project could optionally reference a showcase team instead of retyping the title, description and image. The showcase has its own consent rules for names and photos, which a reference would inherit.
