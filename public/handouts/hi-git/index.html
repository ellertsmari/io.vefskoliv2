The short version

A pull request takes the whole branch

A pull request carries every difference between its branch and vefskoliv2's main. Git and GitHub have no "ignore this file, but only in pull requests" setting.

#122 was opened from dev-hyperisland, the branch you all share. So it brought along everything on it: your handoff notes, the seed script, your local MongoDB setup and a rewritten yarn.lock.

There are two fixes, and together they make it hard to get wrong:

  1. Part 1 Team-only files move into team/, a separate repo that git in the project ignores.
  2. Part 2 Every PR comes from a clean pr/… branch that starts from vefskoliv2's main.

    Who talks to whom

    Push, fetch or pull request?

    You'll do three different things with these repos, and each one only goes in certain directions. Get these right and the rest of this page follows.

    ↑ Push

    Uploads your commits. Goes to your fork, or to the team repo when you're inside team/.

    Never to vefskoliv2.

    ↓ Fetch / pull

    Downloads commits. From vefskoliv2 you only ever fetch: to start a PR branch, and to catch up after a merge.

    → Pull request

    Not an upload. It asks vefskoliv2 to take a branch from your fork. The code arrives there only when it's reviewed and merged.

    The folder you're in decides where a push goes

    The project folder and team/ are two separate repos, and each has its own list of remotes, the places it can push to and fetch from. git remote -v shows that list. After setup, this is what you should see:

    📁 In the project folder

    origin    https://github.com/monika-hyperisland/tomonika-hyperisland.git (fetch)
origin    https://github.com/monika-hyperisland/tomonika-hyperisland.git (push)
upstream  https://github.com/ellertsmari/io.vefskoliv2.git (fetch)
upstream  no-pushing-here (push)
    • origin is your fork. You push and fetch here all the time.
    • upstream is vefskoliv2, there only so you can fetch its main. Its push address is deliberately broken, so an accidental push fails instead of trying.

    📁 Inside team/

    origin  https://github.com/monika-hyperisland/hyperisland-team.git (fetch)
origin  https://github.com/monika-hyperisland/hyperisland-team.git (push)
    • Here origin means the team repo. Same word, different folder, different place.
    • So a git push inside team/ can only ever reach the team repo.

    Part 1 Once

    Give the team its own team/ folder

    team/ sits inside your project folder, so you and your AI assistants can open it like any other folder. It's its own git repo, and the project's git is told to ignore it. Nothing in it can end up on a branch, so nothing in it can end up in a PR.

    1. Create the team repo on GitHub

      Make a new private repository, for example hyperisland-team, and add the rest of the team as collaborators. Leave it empty: no README, no .gitignore.

    2. Tell git to ignore team/, then clone into it

      Run this in the project folder. .git/info/exclude works like .gitignore but is never committed, so it can't show up in a PR either.

      echo "team/" >> .git/info/exclude
git clone https://github.com/monika-hyperisland/hyperisland-team.git team

      Use your repo's real name. Git will warn that you cloned an empty repository. That's expected.

    3. Move the team-only files out of dev-hyperisland

      Copy them into team/ first, then remove them from the shared branch.

      git switch dev-hyperisland
git pull
mkdir -p team/docs
cp docs/raheel-gallery-sort.md team/docs/
cp scripts/seed-test-data.ts team/
cp docker-compose.yml team/
git rm docs/raheel-gallery-sort.md scripts/seed-test-data.ts docker-compose.yml
git commit -m "chore: move team-only files to the team repo"
git push

      The seed script goes straight into team/, not team/scripts/. Its imports (../app/models/…) then still point at the right place.

    4. Push the team repo

      cd team
git add .
git commit -m "Team notes, seed script and local MongoDB"
git push -u origin HEAD
cd ..

      Then tell everyone it's ready.

    1. Save any unpushed edits to the moved files

      If you changed the notes, the seed script or docker-compose and haven't pushed yet, copy those files somewhere safe. Pulling will delete them from the project, and git stops if it would overwrite your edits.

    2. Ignore team/, clone it, pull

      git switch dev-hyperisland
echo "team/" >> .git/info/exclude
git clone https://github.com/monika-hyperisland/hyperisland-team.git team
git pull

    3. Check that git really ignores it

      git status

      team/ must not show up. If it does, the exclude line is missing: run cat .git/info/exclude to check.

    From now on

    • Anything the team needs and vefskoliv2 doesn't (notes, scripts, local setup, experiments) goes into team/. Commit and push it from inside team/.
    • Local MongoDB: docker compose -f team/docker-compose.yml --env-file .env up -d. The --env-file keeps using the .env in the project folder.
    • The seed script: run it the way you did before, but with the path team/seed-test-data.ts.
    • AI assistants: tell them to write handoff notes into team/, not docs/.

    Part 2 Every time

    Open every PR from a clean branch

    Keep working the way you do now: feature branches merge into dev-hyperisland, and that's where the team tests everything together. When something is ready for vefskoliv2, give it a fresh branch that starts from vefskoliv2's main and carries only that feature.

    1. Once: add vefskoliv2 as upstream

      git remote -v

      If no upstream line shows up:

      git remote add upstream https://github.com/ellertsmari/io.vefskoliv2.git

      Then make pushing to it impossible. You only ever fetch from vefskoliv2, so this costs nothing:

      git remote set-url --push upstream no-pushing-here

    2. Start from vefskoliv2's newest main

      git fetch upstream
git fetch origin
git switch -c pr/gallery-controls upstream/main

      Name it pr/ plus what the PR is about. One PR, one topic.

    3. Bring over only the feature's files

      Take the files from the team branch: the code and its tests.

      git checkout origin/dev-hyperisland -- app/components/gallery __tests__/gallerySort.test.ts

      That's a shortened example. The practice section builds the full command for the gallery work. If your commits are already cleanly split per feature, git cherry-pick <commit> works too.

    4. Commit, then look at exactly what the PR will contain

      git commit -m "feat(gallery): search, filters and sort"
git diff --stat upstream/main...HEAD

      That list is your pull request. If something in it shouldn't be there:

      A new file that shouldn't be there

      git rm --cached path/to/file

      A changed file that should match vefskoliv2

      git checkout upstream/main -- path/to/file

      Then git commit again.

    5. Run the checks

      npm run typecheck
npm test

    6. Push it to the fork and open the PR

      git push -u origin pr/gallery-controls
      base repositoryellertsmari/io.vefskoliv2 basemain ← head repositorymonika-hyperisland/tomonika-hyperisland comparepr/gallery-controls

    GitHub can't change the branch an existing PR comes from. Open a new PR from pr/gallery-controls, then close #122 with a comment linking to the new one. Any review feedback on #122 still applies, so make those fixes on the new branch.

      Questions

      Things you might wonder

      Why not just add team/ to .gitignore?

      .gitignore is itself a tracked file, so changing it would show up in your PRs too. .git/info/exclude does the same job and never leaves your laptop.

      Will team/ end up on the fork?

      No. The project's git ignores it, so nothing in it is ever committed to dev-hyperisland or any other branch. It lives only in your own team repo.

      Do tests go in team/ too?

      No. Tests for a feature belong in the PR, because they keep the feature working once it's in vefskoliv2. Only things that help you work go in team/: notes, seed data, local setup.

      I already pushed a note to my pr/ branch. Now what? 
      mv path/to/note.md team/
git rm --cached path/to/note.md
git commit -m "chore: move note to team/"
git push

      The open PR updates by itself. Then commit and push the note from inside team/.

      How do we get vefskoliv2's newest changes into dev-hyperisland? 
      git fetch upstream
git switch dev-hyperisland
git merge upstream/main
git push

      Do this after one of your PRs is merged, so the team branch and vefskoliv2 don't drift apart.

      yarn.lock changed but I didn't add a package

      Installing with a different tool or version rewrites the lockfile. Throw the change away: git checkout upstream/main -- yarn.lock.
